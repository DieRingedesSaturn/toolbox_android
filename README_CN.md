# Toolbox

[English](README.md)

Toolbox 是一个以按需读取为主的轻量 Android 工具箱；另可在明确设置后开启通知快速记账。账本使用本机 SQLite，可选择手动触发 WebDAV 同步；应用无需登录账户，也不依赖固定服务器。实时监控仅在用户主动启动后运行，并使用用户可见的前台服务。

账本菜单中的「通知快速记账」可选开启 Android 通知读取，并选择来源应用。应用只在本机对这些新通知提取金额：只保留带货币标记（`¥`/`￥`、`元`、`CNY`/`RMB`/`人民币`）或写成两位小数的数字，紧跟在「余额」后面的数字会跳过，含验证码字样的通知整条忽略，因此卡号尾号、日期、订单号和验证码都不会成为候选。所选应用的每条通知随后只在本机保留最多 7 天——含标题和正文，最多 30 条候选加最近 15 条被跳过的记录——「记录」页会列出实际收到的内容、识别出的金额以及跳过原因（没有金额、验证码通知或无文本）；清空列表或关闭功能都会删除它们。来源感知解析器会按明确的动词（已支付、付款成功、收款、退款、转账、支出等）识别微信支付和支付宝的通知，并给候选标注方向、金额，以及通知中出现的商户/对方。在「来源应用」中可为每个已选应用设置默认收支类型、账户和多个标签，并可选开启自动入账；这些设置仅保存在本机，不包含在账本 JSON / WebDAV 备份中。自动入账只会把高置信的支出/收入直接写入账本（标题用商户或渠道名，时间用通知时间，账户和标签用该来源的默认值）；转账因需要两个账户仍只给建议，低置信和疑似重复的通知也仍需确认。已自动入账的候选会显示「撤销」，可删除对应账目。点选金额会预填现有编辑器，保存前仍可修改。默认账户已删除或归档时回退到有效的上次使用账户或默认账户，已删除的标签会忽略。保存通知候选时会查询当前账本：若同一账户前后 5 分钟内有金额、币种、收支类型相同的账目，会提示返回编辑、仍然保存，或作为已记账通知忽略。通知覆盖率取决于支付应用本身：微信通过「微信支付」服务消息发通知，该通道被静音或某些场景不通知时就不会有；部分应用内支付/离线支付可能完全不发通知，支付宝离线支付也可能延迟到达。关闭功能会清空全部通知记录并停用通知监听，即使系统里的通知读取权限还开着，系统也不再把通知发给本应用。系统授予的通知读取范围较广，来源应用筛选发生在 Toolbox 收到通知之后。此功能不会主动联网，也不启动常驻前台服务。

开发前请阅读英文开发规范 [AGENTS.md](AGENTS.md)。完整目录约定和后续功能的落位规则见 [docs/PROJECT_STRUCTURE_CN.md](docs/PROJECT_STRUCTURE_CN.md)。

## 当前范围

- `Device`：手机身份、Android/API、内核、SoC/CPU、ABI、核心数、内存、存储、显示、电池，以及基础 GPU 能力摘要。
- `Live monitor`：可选的紧凑半透明悬浮窗折线图，显示 CPU、GPU、内存、电量和 FPS 参考值，并可自定义显示项目。监控页按核心显示 CPU 当前频率，同时显示 GPU/显示详情和热状态详情；悬浮窗可在逐核心频率和按峰值频率加权的 CPU 占比之间切换。CPU/GPU 优先读取真实占用率；Android 只提供频率时用 `≈` 标记频率占比估算，受系统限制的源明确显示不可用。
- 监控页还会在公开 API 提供时显示电池温度、Android 系统热状态、热余量、当前显示刷新率和支持的显示模式。悬浮窗与整个软件均支持 Everforest 自然森绿深浅主题配色（深色、浅色、跟随壁纸的动态色与自定义主题色），自适应文字与图表高对比度；悬浮窗支持锁定位置与触控穿透，移动后会保存上次位置。
- `Location`：按需获取当前位置，显示十进制度/DMS 坐标、精度、提供方、GPS 提供方高度、时间、按需卫星扫描中实际观测到的导航系统及可用/已启用定位源，并支持按需查询地表地形海拔（DEM 模型）。只有用户开始定位后才请求前台位置权限。
- `Network`：按需显示连接方式、接口、本地地址、DNS、网关和按流量计费状态；公网 IP、大致位置、运营商、ASN、组织、主机名、IP 段、网络类型以及免费的代理/VPN/风险提示查询是单独的手动操作；仅在你点击查询时访问 ipwho.is 与 proxycheck.io（失败时回退 ipapi.co/ipify），只发送所查询的 IP，并可跳转到浏览器打开 IPLark 的完整报告。代理/VPN 标记与风险评分是针对所查询出口 IP 的第三方启发式结果，不代表本机是否正在使用 VPN。可手动「开始扫描」列出局域网设备：对子网做 ARP 发现 + 短端口表 TCP 探测，并收集 mDNS/SSDP/ONVIF WS-Discovery 服务通告；开放摄像头典型服务/端口（RTSP、大华/雄迈/海康/ONVIF 等）或网卡为摄像头厂商的设备会被标注为启发式提示——自带热点、仅连云或不开端口的摄像头无法被发现，界面里有如实说明。扫描仅在点击时运行、可取消，期间才加入组播（`CHANGE_WIFI_MULTICAST_STATE`，安装期权限）。
- `Ledger（记账与平均使用成本）`：支持日常收支记账，分为概览（本月收支、最近记录、支出分类，以及近 6 个月收支趋势——点月份跳到该月明细；记账页菜单的「概览卡片排序」可拖动调整这些卡片的位置，默认最近记录靠前）、明细（按日分组、按月切换）、成本（大件摊销与订阅日均）与账户四个标签页，可左右滑动切换，内置收支分类，并可在记账时开启「计入平均成本」，区分**一次性长期大件（如买断手机/电脑的按日、按月折旧摊销）**与**周期性订阅（按周/月/季/半年/年或自定义每N天/周/月/年，日均月均折算与续费追踪）**。使用 Android 原生 `SQLiteOpenHelper` 持久化，内置 `uuid`、毫秒级时间戳与软删除墓碑，按「最后写入者胜」合并；不依赖任何固定服务器。每次数据库结构升级前，会先把旧数据库文件复制到不参与备份的应用私有目录（保留最近 3 份），即使升级逻辑出错，升级前的数据也还在；记账页菜单的「恢复升级前副本…」会列出这些副本，恢复时先在临时数据库中校验并升级所选副本，再保存当前账目、标签与账户的恢复副本，最后用一笔 SQLite 事务整体替换这些记录；失败时保留原账本，恢复成功后才裁剪旧副本。若升级前副本无法保存，会停止升级，并在账本页显示错误与重试按钮。主屏幕小组件显示日均成本与本月支出，并提供快速记一笔按钮；不需要额外权限，记录变化时即时刷新，并由系统小组件调度器约每 3 小时更新，不运行后台服务。本地备份通过系统文件选择器完成：JSON 导出为完整可再导入的备份（含删除标记），CSV 导出为表格；导入时可选择「合并」或「替换」，全程不需要存储权限。记账页菜单还提供手动 WebDAV 备份与同步：仅在用户主动点击时运行，仅支持 HTTPS，且只写入你在服务器上预先创建的文件夹（`ledger.json`、按日期命名的 `ledger-backup-*.json` 快照——仅保留最新 10 份，可将快照下载后通过「替换」导入恢复——以及 `ledger-backups.json` 索引）。密码经 Android Keystore 加密后仅保存在本机，不新增权限、依赖或后台任务。由于账本不参与系统自动备份，当距上次 JSON 导出或 WebDAV 同步（从未备份时按最早的数据算）已满 7 天、且这期间账本有改动时，记账页会显示备份提醒，可直接导出 JSON 或 WebDAV 同步；点「稍后」隐藏 7 天。可选的月度预算（总额与按标签，单位人民币，在记账页菜单或概览本月卡片中设置）会显示进度条、剩余或超支金额，以及本月剩余每天可用多少；预算只保存在本机，不包含在 JSON 备份和 WebDAV 同步中。新建记录时，近 90 天里记过至少两次的名称会显示为「常用」按钮，点一下即可填好类型、名称以及最近一次的金额、币种、标签和账户；这些按钮由已有记录推算，不额外保存或同步任何数据。记录支持自定义多标签（原 12 个内置分类仅在旧记录引用时转为可编辑标签；新安装不再预置标签）。标签可重命名、换色、从推荐预设选 emoji、排序、合并，并可对多选记录批量添加/移除；标签详情页显示笔数与累计收支。明细与成本页可按标签以「任一/全部」筛选，概览页按标签统计支出。周期订阅与周期性固定收入按期确认：待确认卡片按日历日期列出到期续费，每次记录的续费会成为一条独立交易并锁定当日汇率（已跳过的续费不再提示）；在某日停订时，恰在当天的续费不算已扣款。两种成本模式都可以设置可选的结束日期（必须晚于记账日期）：当天仍然计入，之后不再计入；订阅不会生成落在该日或之后的续费，一次性资产改按从记账日到该日的天数摊销（代替预计使用天数），到期后显示为「已摊销完」，并退出日均成本统计。一次性大件可在所选日期「卖出」或「报废」：卖出会生成一条关联的收入记录，最终成本为买价减去卖价；已处置的大件不再计入日均成本，且可撤销。账目币种支持人民币（CNY，默认）、日元（JPY）、美元（USD）与欧元（EUR）：外币账目在保存时锁定当日的 CNY 汇率，因此所有合计、摘要、小组件与成本计算始终统一为人民币，历史总额不会随汇率波动。汇率按显式的按需回退链获取——Frankfurter（api.frankfurter.dev）→ 欧洲央行官网（www.ecb.europa.eu）→ 社区 currency-api（cdn.jsdelivr.net，其次 *.currency-api.pages.dev）——请求仅携带日期或日期范围，实际使用的来源会记录在每条账目中（手动输入记为 manual）；所有来源失败时可选择最近缓存汇率或手动输入。每条账目都记在一个账本上——账户页（第 4 个标签）可管理多个账户（名称、币种、期初余额与日期、颜色、图标），显示各账户余额与按缓存汇率折算的人民币总资产（缺少汇率的账户不计入并标注）。账目类型支持支出、收入与账户间转账；转账不计入收支统计；账户详情里的「校准余额」会在计算余额与实际不符时写一条有符号的余额调整记录（调整只显示在该账户的流水里，不进入明细列表，也不计入收支统计）。账户与账目、标签一样走 LWW 备份/WebDAV 载荷。
- `Currency converter（汇率换算）`：以欧元为基准的参考汇率，按回退链获取且无需 API Key——Frankfurter（api.frankfurter.dev）→ 欧洲央行 eurofxref（www.ecb.europa.eu）→ 社区 currency-api（cdn.jsdelivr.net，其次 *.currency-api.pages.dev）；界面会标注实际使用的来源，社区来源的数值可能与欧洲央行略有差异。输入金额并选择源币种（四个记账币种在前，另可展开全部已发布币种并显示本地化名称；在列表里点星标可把常用货币固定到记账币种旁边，同时出现在币种按钮和换算结果中），按各币种自身小数位换算。汇率仅在你主动点击刷新（或首次「获取汇率」）时联网获取，随后缓存到本机（最新汇率 + 近期历史日期）供离线使用，并始终标注汇率日期与来源；发送到这些主机的只有请求日期。
- Device 页与各模块所有信息行点击即可复制。

v0.1 暂不实现测速、Shizuku/root、进程管理、第三方重型 ORM 或广告分析。基于 Shizuku 的高级权限数据读取属于后续计划，不是当前依赖。

## 实时监控权限

启动实时监控需要 `SYSTEM_ALERT_WINDOW`，用户需在系统设置中允许悬浮窗；同时声明前台服务权限，并在 Android 13+ 请求 `POST_NOTIFICATIONS`，以显示服务状态和停止操作。监控每秒采样一次，可从监控页或通知停止，不会开机自启。普通应用可能无法读取系统级 CPU/GPU 占用文件，界面会如实说明限制，不伪造数据。电池温度、系统热状态和热余量使用 Android 公开 API；精确 CPU/GPU 温度及厂商专用 GPU 占用率在没有受信任系统权限时可能不可用。FPS 项目当前以显示刷新率作为尽力而为的参考值；跨应用真实渲染 FPS 需要 SurfaceFlinger 特权访问，留给后续 Shizuku 计划。

模拟定位位于「位置 → 设置模拟位置」：Debug 构建会声明 `ACCESS_MOCK_LOCATION`，才会出现在开发者选项的「选择模拟位置信息应用」列表中；声明本身不会开启模拟，仍需在该列表中选中 Toolbox。先在 Android 开发者选项中选择 Toolbox，再手填 WGS84 坐标、在地图上点选（内置 MapLibre GL JS 4.7.1，打开选点页时才向 tiles.openfreemap.org 拉取 OpenFreeMap 矢量瓦片；无地理编码、无 API 密钥），或主动点击按钮用当前网络出口 IP 的大致位置预填（ipwho.is，失败时回退 ipapi.co）。IP 坐标会受 VPN/代理影响，不代表实际位置；用 IP 预填不会改动精度半径。上次使用的精度半径会自动记住，该值是可修改的模拟值，并非测得的误差。模拟使用系统测试定位源（GPS、网络，以及存在时的 fused），保留可识别的模拟标记，不会替其他应用授予定位权限，也不保证第三方融合定位 SDK 接受。手动开启 15/30/60 分钟会话后，立刻出现常驻状态通知（标题「模拟定位已开启」，含剩余时间和坐标，可点停止），约每秒提交新时间戳，可切换至其他应用；必须允许通知。服务不读取真实 GPS，不新增依赖、后台定位权限或其他敏感权限，只按需使用已有通知权限，不开机启动、不自动重启。会话到时、手动停止、划掉 Toolbox 任务或出错时停止；休眠时不持有唤醒锁，唤醒后继续按已过时长判断结束。正常停止会移除本次测试源，但其他应用可能暂时保留缓存，真实定位需要重新获取。只持久记录测试源名称用于异常清理，不保存坐标历史；若中断后仍有清理记录，页面提供重试入口。若已撤销模拟授权，需重新选择 Toolbox 后清理，或在开发者选项撤销模拟应用，再获取真实定位。普通定位读数会标注模拟位置。**仅供学习与合法测试，不可用于违法用途。**

位置模块仅在用户主动开始定位时申请 `ACCESS_COARSE_LOCATION` / `ACCESS_FINE_LOCATION` 前台权限，不申请后台定位；地表地形海拔（DEM）仅在用户手动点击后单次查询。网络状态使用系统自动授予的 `ACCESS_NETWORK_STATE` 和 `INTERNET` 权限；公网 IP 与地理位置操作只在手动触发时向公开地址服务发起一次请求，不会自动轮询。

账本包含财务记录，因此关闭 Android 系统自动备份；请使用账本内的手动 JSON 导出或 WebDAV 同步备份。WebDAV 服务器必须为已有的 `ledger.json` 提供强 ETag 并支持条件写入，否则应用会在覆盖前停止同步。应用流量总计按 UID 去重；系统以特殊热点 UID 记录的热点/USB/蓝牙/P2P 共享流量会计入 WLAN/移动总计，并单独显示为“共享网络流量”，但无法归属到本机单个应用或分类。部分厂商可能不公开 P2P 本地侧计数；其他共享或无法识别的 UID 流量同样不计入应用明细，读取失败时显示不可用。卫星导航系统列表只显示实际观测到的星座。

## 开发环境

- Android Studio Quail 3 (2026.1.3 Patch 1)
- Android SDK Platform 36、Build Tools 36.0.0、Platform Tools 37.0.1
- JDK 21（Android SDK 36 的 Robolectric 测试需要 Java 21；应用字节码仍以 Java 17 为目标）
- Kotlin + Jetpack Compose
- minSdk 26，targetSdk 36

使用 Android Studio 打开仓库并让 Gradle 同步配置的依赖。命令行流程为：

```bash
./gradlew assembleDebug
./gradlew installDebug
./gradlew installRelease
adb logcat
```

Debug 构建没有 R8 优化，也用不上随包的 baseline profile，Compose 界面明显更慢；日常使用请安装 release 构建。项目根目录下存在不提交的 `signing/toolbox-debug.keystore` 时，debug 和 release 都用它签名，两者可以互相覆盖安装，数据不丢；没有这个文件时，debug 回落到默认调试密钥，release 不签名。release 构建不可调试，`adb shell run-as` 读不到应用文件，备份请用 App 内的 JSON 导出或 WebDAV。

单元测试包含通过 Robolectric 在 JVM 上运行的 SQLite 数据库升级测试。Robolectric 只用于测试（Apache-2.0），不会打包进 App；第一次运行 `./gradlew testDebugUnitTest` 时会从 Maven Central 下载它的 Android 框架包。

如果当前 shell 尚未配置 JDK 21 和 Android SDK，请将 `JAVA_HOME` 与 `ANDROID_SDK_ROOT` 指向本机安装位置。SDK 路径保存在不提交的 `local.properties` 中。
